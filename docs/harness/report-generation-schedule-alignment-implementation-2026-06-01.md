# Report Generation Schedule Alignment Implementation

Date: 2026-06-01

## Objective

Implement the scheduled-report-only target from `docs/harness/report-generation-schedule-alignment-plan-2026-06-01.md` while limiting automatic AI report generation to five cost-controlled representative assets:

- `DGS10` - US 10Y Treasury
- `XAU` - Gold, the app's canonical gold detail ticker
- `BTC-USD` - Bitcoin
- `NVDA` - NVIDIA
- `005930.KS` - Samsung Electronics

## Behavior Changes

- The backend scheduler now uses `REPORT_SCHEDULER_INTERVAL_HOURS=6` and `REPORT_SCHEDULER_ASSET_COOLDOWN_HOURS=6` by default.
- Scheduled report generation seeds and iterates only `REPORT_SCHEDULER_TARGET_TICKERS`, defaulting to `DGS10,XAU,BTC-USD,NVDA,005930.KS`.
- A deployment-start catch-up report job is registered in the scheduler so the limited target set can be generated immediately after startup, subject to the same cooldown and per-run cap.
- `REPORT_SCHEDULER_MAX_REPORTS_PER_RUN` now defaults to `5`, matching the representative target set.
- `POST /api/ai/generate/{ticker}` no longer performs LLM-backed generation for ordinary authenticated users; it raises `403` and points callers to scheduled generation.
- `AssetDetail.jsx` no longer calls `POST /api/ai/generate/{ticker}` when `GET /api/reports/{ticker}` returns `404`.
- The AI report card now has a scheduled-report-pending state for missing stored reports.
- User-facing requests and chatbot report answers read stored scheduled reports only; they do not trigger report generation.

## Follow-Up Risks

- The startup catch-up job can still consume LLM/API quota for up to five reports when scheduler and LLM configuration are enabled.
- Gold is scheduled as `XAU`, because the current app's commodity cache/detail route uses `XAU` as the canonical ticker while mapping gold news to `GC=F`.
- Assets outside the five-ticker catalog can show a scheduled-report-pending state indefinitely unless the target list is expanded or reports are generated by an approved backend process.
- The manual generation endpoint remains present for compatibility but is disabled for normal use; a future admin workflow would need explicit authorization design.
