# 3. 기능상세 명세서

기준: `docs/harness/feature-index.md`의 기능 단위 + 현재 코드. 보조: `PROJECT_FUNCTION_DETAIL_SPEC.md`.

각 기능을 **입력 / 처리 / 출력 / 권한 / 예외** 로 정리한다.

## 3.1 인증 (Google 로그인)

| 항목 | 내용 |
| --- | --- |
| 입력 | Google ID Token (프론트 Google 로그인 위젯) |
| 처리 | `google-auth`로 ID Token 검증 → `google_sub`/`email`로 User 조회·생성 → JWT 발급 |
| 출력 | `access_token`, 사용자 정보(닉네임 등) |
| 권한 | 누구나 |
| 예외 | 토큰 검증 실패 시 401 |

- 주관: `backend/app/api/auth.py`, `core/security.py`, `core/config.py`, `frontend/src/pages/Login.jsx`, `store/authStore.js`
- 비고: 이메일/비밀번호 로그인·회원가입은 사용하지 않는다(Google 단일 흐름).

## 3.2 프로필 / 닉네임

| 항목 | 내용 |
| --- | --- |
| 입력 | 닉네임 문자열 |
| 처리 | 닉네임 중복 검사 → 갱신 → `nickname_confirmed_at` 기록 |
| 출력 | 프로필 정보, 닉네임 사용 가능 여부 |
| 권한 | 로그인 사용자 |
| 예외 | 중복 닉네임 거부 |

- 주관: `backend/app/api/profile.py`, `services/profile_service.py`, `frontend/src/pages/MyPage.jsx`

## 3.3 시장 데이터 (가격·뉴스·히스토리)

| 항목 | 내용 |
| --- | --- |
| 입력 | (조회) 없음 / 히스토리 `period`(`1d,1mo,1y,5y`) |
| 처리 | 스케줄러가 외부 API 수집·정규화 후 메모리 캐시 갱신, 조회는 캐시 응답 |
| 출력 | 카테고리별 `currentPrice`, `changePercent`, 미니 차트, 시가총액, 뉴스 |
| 권한 | 누구나 |
| 예외 | 외부 API 실패 시 직전 값 carry-forward / stale 캐시 유지 |

- 지원 카테고리: INDEX, STOCK_US, STOCK_KR, BOND_US, BOND_KR, COMMODITY, CRYPTO, 환율
- 외부 소스: Finnhub, CoinGecko, 공공데이터포털, Stooq, FRED, Naver 뉴스, open.er-api.com
- 주관: `backend/app/main.py`(라우트), `services/market_service.py`, `price_providers.py`, `macro_service.py`, `core/cache.py`

## 3.4 자산 상세

| 항목 | 내용 |
| --- | --- |
| 입력 | 티커, 기간 |
| 처리 | 시장 캐시에서 티커 매칭 → 히스토리 조회 → (권한 시) 리포트 조회 → 댓글 조회 |
| 출력 | 현재가/등락률, 기간별 차트, AI 리포트, 댓글 목록 |
| 권한 | 시세/댓글 조회는 누구나, 리포트는 PLUS 이상 |
| 예외 | 채권은 가격 차트 대신 매크로 분석 중심 안내 |

- 주관: `frontend/src/pages/AssetDetail.jsx`, `components/ReportCard.jsx`

## 3.5 AI 리포트

| 항목 | 내용 |
| --- | --- |
| 입력 | 티커(스케줄 배치 대상) |
| 처리 | LangGraph: financial/news/macro 수집 → synthesizer 통합 → writer 작성 → evaluator 평가(미통과 시 재작성 루프) |
| 출력 | `final_content`(Markdown), bull/bear 요약, 품질 메타데이터 |
| 권한 | 열람 PLUS 이상 |
| 예외 | 시장 캐시에 티커 가격이 없으면 생성 불가, 평가 한도 도달 시 최종본 반환 |

- 정책: **사용자/챗봇 요청은 실시간 생성을 트리거하지 않음**(저장된 스케줄 리포트 조회 기본). AGENTS.md 섹션 14.
- 주관: `backend/app/services/ai_service.py`, `services/graph/`

## 3.6 커뮤니티 (종목 토론방)

| 항목 | 내용 |
| --- | --- |
| 입력 | 자산 식별자(ID 또는 티커), 댓글 내용 |
| 처리 | 댓글 CRUD, 좋아요 토글, 신고(중복 차단), 닉네임/좋아요 수 조인 |
| 출력 | 작성자 닉네임 포함 댓글 목록(최신순), 좋아요 수 |
| 권한 | 조회는 누구나, 작성/수정/삭제/좋아요/신고는 로그인 사용자(수정·삭제는 본인) |
| 예외 | 공백 댓글 422, 타인 댓글 수정/삭제 403, 중복 신고 차단 |

- 주관: `backend/app/api/community.py`, `models.py`(Comment/CommentLike/CommentReport)

## 3.8 알림 (Email / Telegram)

| 항목 | 내용 |
| --- | --- |
| 입력 | 수신 동의, 채널 목적지(이메일/chat_id), 가격 변동 임계값 |
| 처리 | 채널 연결·검증, 가격/뉴스/리포트 변화 평가 + 정시 요약 생성, 미발송 알림 배치 발송 |
| 출력 | 알림 이벤트, 발송 이력 |
| 권한 | PLUS 이상 |
| 예외 | 미검증 채널 발송 안 함, dedupe_key로 중복 발송 차단, quiet hours 적용 |

- 주관: `backend/app/api/notifications.py`, `services/notification_service.py`, 모델 NotificationPreference/Channel/Rule/Event/Snapshot

## 3.9 구독 / 결제

| 항목 | 내용 |
| --- | --- |
| 입력 | 요금제 선택, Toss 빌링 인증 결과 |
| 처리 | checkout 생성 → 빌링키 등록 → 구독 활성화(Mock 즉시 활성화) → 등급별 entitlement 산출 |
| 출력 | 현재 구독/등급, entitlement(`can_view_reports`, `can_use_chatbot`, `can_use_notifications`) |
| 권한 | 로그인 사용자 |
| 예외 | webhook 멱등 처리(`provider_event_id` 유니크), 중복 구독 유니크 제약 |

- 등급: FREE(열람·챗봇·알림 모두 불가) / PLUS(리포트+알림) / PRO(리포트+알림+챗봇)
- 주관: `backend/app/api/billing.py`, `services/subscription_service.py`, `services/payment_service.py`

## 3.10 챗봇

| 항목 | 내용 |
| --- | --- |
| 입력 | 사용자 메시지(멀티턴, 최대 10턴 문맥) |
| 처리 | LLM 의도 이해 → 도구 호출(시세/리포트 조회 등) → 응답 생성 |
| 출력 | 챗봇 답변, 액션 카드 |
| 권한 | PRO 등급만 (런처 노출 자체가 `can_use_chatbot` 게이팅) |
| 예외 | 비PRO는 챗봇 UI 미노출 |

- 정책: 챗봇은 저장된 리포트를 읽으며 실시간 리포트 생성을 트리거하지 않는다.
- 주관: `backend/app/api/chat.py`, `services/chat_service.py`, `chat_llm.py`, `chat_tools.py`, `frontend/src/components/Chatbot*.jsx`
