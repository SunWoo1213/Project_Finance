# 7. 방학 목표

> 본 문서는 **초안**이다. 최근 `docs/harness/` 변경 기록과 현재 미완 과제를 근거로 작성했으며, 실제 기간·세부 일정은 `[보완 필요]`로 표시했다. 학사 일정/팀 합의 후 채운다.

## 7.1 기간 및 전제

- 방학 기간: `[보완 필요: 예) 2026-06-XX ~ 2026-08-XX]`
- 팀 구성/역할: `[보완 필요]`
- 목표 한 줄: 데모 수준에서 운영 가능한 **안정적인 AI Invest 서비스**로 완성도를 끌어올린다.

## 7.2 현재까지의 진행 상황 (근거: 최근 변경 기록)

- 핵심 기능 구현 완료: Google 로그인, 시장 데이터(캐시 기반), 자산 상세, AI 리포트(LangGraph), 커뮤니티, 즐겨찾기, 알림(Email/Telegram), 구독·결제(Toss Mock), 챗봇.
- 최근 집중 영역: 시장 데이터 provider 안정화(Stooq/FRED 전환, 나스닥·환율 표시 보정), AI 리포트 생성 파이프라인 복구, 알림 발송 신뢰성(Gmail/Telegram), 정기 요약 알림.
- 배포: Vercel(FE) / Render(BE) / Supabase(DB) 구성.

## 7.3 방학 목표 마일스톤 (초안)

### M1. 데이터 파이프라인 안정화 — `[보완 필요: 기간]`
- 시장 provider 장애/키 소진에 대한 복원력 강화(폴백·상태 모니터링) 완성.
- 캐시 stale 처리·carry-forward 동작 회귀 테스트 추가.

### M2. AI 리포트 품질·신뢰성 — `[보완 필요: 기간]`
- 리포트 생성 실패율 감소(fact_checker 루프, 평가 통과율 모니터링).
- 자산군별(주식/채권/원자재/코인) 프레임워크 품질 점검.
- 스케줄 생성 커버리지 확대 및 비용 가드 유지(사용자 실시간 생성 금지 정책 유지).

### M3. 결제·구독 실연동 검토 — `[보완 필요: 기간 / 실결제 도입 여부 결정 필요]`
- 현재 Mock 즉시 활성화 → 실 Toss 빌링 연동 여부 결정 및 테스트.
- 등급별 entitlement(FREE/PLUS/PRO) 경계 케이스 검증.

### M4. 사용성·UI 다듬기 — `[보완 필요: 기간]`
- 모바일 반응형, 로딩/에러 상태 정리.
- 인코딩 깨진 잔여 문자열 정리(기존 문서·일부 UI).

### M5. 테스트·문서·발표 준비 — `[보완 필요: 기간]`
- 백엔드 핵심 서비스 pytest 커버리지 확대.
- 본 산출물(흐름도/ERD/API/명세) 최신화 유지.
- 최종 발표 자료(PPT) 작성.

## 7.4 리스크 / 의존성

- AI 리포트 LLM 비용: 배치 주기·재작성 한도로 관리 필요.
- 무료 티어 외부 데이터 한도: provider 다변화로 대응 중.
- 실결제 도입 시 규정/보안 검토 필요(`[보완 필요: 의사결정]`).

## 7.5 보완이 필요한 항목 (사용자 입력 대기)

1. 방학 실제 기간과 각 마일스톤 시작/종료일.
2. 팀원 역할 분담.
3. 실결제(Toss) 실연동 진행 여부.
4. 추가하고 싶은 신규 기능(있다면).
